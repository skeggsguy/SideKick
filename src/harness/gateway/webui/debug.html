Sidekick (debug)

Installing this page's icon creates a home-screen app whose launch arms the ?recoverdebug=1 recovery capture — the one thing the normal Sidekick icon cannot do: its start_url is /, so the param is gone before the app boots.

Install (iPhone / iPad)

  1. Open this page in Safari on the device.
  2. Check the URL bar still reads /debug.html — this page never redirects, and the debug manifest is only read when this page is the one being added.
  3. Share → Add to Home Screen → name it Sidekick (debug) → Add.
  4. Launch that icon — not the normal Sidekick one. Both icons coexist; the normal one must keep opening un-armed.

Is it armed?

Armed = a trace block in the transcript — above the messages while they stream, at the end after a re-render — whose lines open with an event-time stamp. A run of consecutive no-op endThinking closes collapses into a single ×N line, so the block grows more slowly than the event log.

No trace after launching the debug icon: STOP and report — never run the device check blind. A suspend/resume failure without the capture is undiagnosable; that is the whole reason this icon exists.

Safari-tab session (no install)

Open Sidekick with the capture armed (Safari tab) — the BK-019 vehicle: works in a browser tab only, never from a home-screen icon.
